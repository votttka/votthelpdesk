# Бизнес-требования HelpDesk Prototype

Источник: файл бизнес-требований заказчика (50 требований)

## Приоритетные требования для MVP

### 1. Единая система для всех типов обращений
- Система должна поддерживать все типы обращений в едином интерфейсе
- Инциденты, запросы на обслуживание, платные работы, внутренние задачи

### 2. Обязательная типизация заявок
- При создании заявки обязательно указание типа из справочника
- Если выбран тип «Другое», требуется обязательный комментарий

### 3. Статусная модель с паузой
- Статусы: Новая, В работе, Ожидание клиента, Ожидание смежника, Решена, Закрыта
- При переводе в «Ожидание клиента» или «Ожидание смежника» обязательна причина паузы
- Событие паузы фиксируется в аудит-логе

### 4. Канал решения обязателен при закрытии
- При переводе в «Решена» обязателен канал решения:
  - Удалённо
  - Телефон
  - Переписка
  - Выезд
- Без канала решение не сохраняется

### 5. Полный аудит-лог событий
- Создание заявки
- Смена статуса
- Комментарии
- Назначение исполнителя
- Передача между линиями
- Закрытие
- Изменение типа
- Другие ключевые события

### 6. Запрет передачи между линиями без комментария
- Передача заявки между линиями поддержки только с обязательным комментарием
- Без комментария передача блокируется

### 7. Признак «Клиентская / Внутренняя»
- Каждая заявка должна иметь признак принадлежности
- Клиентская — от внешнего заказчика
- Внутренняя — от сотрудников организации

### 8. Вкладка «Взаимодействия»
- Комментарии по заявке
- Фиктивные звонки (эмуляция)
- Фиктивные подключения (эмуляция)
- Хронология взаимодействий

### 9. Единый поиск заявок
- Поиск по номеру заявки
- Поиск по контрагенту
- Поиск по названию/описанию
- Фильтры по статусу, типу, признаку клиентская/внутренняя

### 10. Готовые базовые отчёты или дашборд-сводка
- Количество заявок по статусам
- Количество по типам
- Клиентские и внутренние
- Заявки с паузой
- Заявки без типа или с типом «Другое»
- Потенциальные просрочки (если возможно)

### 11. Разграничение прав через простую эмуляцию ролей
- Оператор
- Инженер
- Лид
- Аудитор
- Администратор
- Для прототипа допустима ручная смена роли без настоящей авторизации

### 12. Заглушки обязательных интеграций
- Телефония: запись и метаданные звонка как мок
- УСП: входящая заявка от госзаказчика как мок
- Бухгалтерия: список списанных часов как мок
- Аналитика: экспорт события или JSON-выгрузка
- SSO: кнопка или поле эмуляции входа
- Трекер разработки: создание связанной задачи как мок

## Требования к данным и безопасности

### Разрешённые данные
- Только синтетические данные
- Вымышленные клиенты
- Вымышленные контрагенты
- Тестовые заявки
- Тестовые пользователи
- Фейковые звонки
- Фейковые интеграции

### Запрещённые данные и действия
- Нельзя использовать реальные персональные данные
- Нельзя использовать реальные данные госконтрактов
- Нельзя хранить секреты в репозитории
- Нельзя обращаться к внешним реальным системам без явного разрешения
- Нельзя удалять аудит-лог в интерфейсе
- Нельзя менять утверждённые решения без фиксации

## Требования к инфраструктуре

### Запрещено
- Локальные компьютеры, ноутбуки, рабочие станции
- Mac, Windows-машины или личные/корпоративные ПК
- Физические серверы
- Ручные установки на чужом оборудовании
- Локальные базы данных, требующие администрирования на машине пользователя

### Разрешено
- Git-репозиторий как единственный источник кода, задач, решений и артефактов
- Issues / Projects / Boards для планирования
- Pull Requests для merges и review
- CI/CD на базе бесплатных или доступных облачных runner'ов, по умолчанию Linux
- Статический хостинг для фронтенда (GitHub Pages, Netlify, Vercel, Cloudflare Pages)
- Браузер как основная среда проверки
- Бесплатные управляемые сервисы, если они не требуют оплаты
- Локальное хранение данных в прототипе через localStorage / IndexedDB / JSON-файлы / SQLite-файл в репозитории
