## Принятые решения

### [DEC-001] Технологический стек: Vue 3 + Vite + localStorage
- **Статус**: accepted
- **Автор**: HQ / Штаб
- **Дата принятия**: 2025-01-09
- **Связанные предложения**: [PROP-001](proposals.md), [PROP-002](proposals.md)
- **Описание**: 
  - Фронтенд: Vue 3 с Composition API
  - Сборка: Vite
  - Хранилище: browser localStorage
  - Деплой: GitHub Pages / статический хостинг
- **Обоснование**: 
  - Минимальная конфигурация
  - Работает без сервера
  - Быстрая разработка MVP
  - Соответствует ограничениям инфраструктуры
- **Последствия**: 
  - Требуется Node.js для сборки (в CI)
  - Данные хранятся только в браузере клиента
  - Нет бэкенда в классическом понимании

### [DEC-002] GitHub Actions для CI/CD и проверок Архитектора
- **Статус**: accepted
- **Автор**: HQ / Штаб
- **Дата принятия**: 2025-01-09
- **Связанные предложения**: [PROP-003](proposals.md)
- **Описание**: 
  - Использовать GitHub Actions для CI/CD
  - Настроить scheduled workflow каждые 30 минут для проверок Архитектора
  - GitHub Pages для хостинга прототипа
- **Обоснование**: 
  - Бесплатно для публичных репозиториев
  - Нативная интеграция с GitHub
  - Поддержка cron-расписаний
- **Последствия**: 
  - Лимиты GitHub Actions (2000 минут/месяц для бесплатного тарифа)
  - Проверки Архитектора могут потреблять квоту

### [DEC-003] Эмуляция ролей без реальной авторизации
- **Статус**: accepted
- **Автор**: HQ / Штаб
- **Дата принятия**: 2025-01-09
- **Связанные предложения**: [PROP-004](proposals.md)
- **Описание**: 
  - Реализовать переключатель ролей в UI
  - Роли: Оператор, Инженер, Лид, Аудитор, Администратор
  - Без настоящей аутентификации и авторизации
  - Явно пометить как эмуляцию для прототипа
- **Обоснование**: 
  - Упрощает разработку MVP
  - Достаточно для демонстрации функционала
  - Не требует OAuth/SSO инфраструктур
- **Последствия**: 
  - Не является системой безопасности
  - Требует явной маркировки в интерфейсе
  - В будущей версии потребуется реальная авторизация

### [DEC-004] Mock-слой для всех внешних интеграций
- **Статус**: accepted
- **Автор**: HQ / Штаб
- **Дата принятия**: 2025-01-09
- **Связанные предложения**: [PROP-005](proposals.md)
- **Описание**: 
  - Создать единый mock-сервис для интеграций
  - Интеграции: телефония, УСП, бухгалтерия, аналитика, SSO, трекер задач
  - Все данные синтетические
  - Явно маркировать непроверенные места
- **Обоснование**: 
  - Нет доступа к реальным системам
  - Позволяет развивать интерфейс независимо
  - Не блокирует разработку
- **Последствия**: 
  - Интеграции требуют будущей реализации
  - Mock-данные должны быть реалистичными
  - Требуется документация по контрактам

### [DEC-005] Структура статусов заявки
- **Статус**: accepted
- **Автор**: HQ / Штаб
- **Дата принятия**: 2025-01-09
- **Описание**: 
  - Новая → В работе → Ожидание клиента / Ожидание смежника → Решена → Закрыта
  - Пауза таймера при статусах «Ожидание»
  - Обязательная причина при переходе в паузу
- **Обоснование**: 
  - Соответствует бизнес-требованиям
  - Стандартная модель для helpdesk
- **Последствия**: 
  - Требуется валидация переходов
  - Аудит-лог должен фиксировать все переходы
