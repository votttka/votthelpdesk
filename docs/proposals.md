## Активные предложения

### [PROP-001] Использование Vue 3 с Composition API для фронтенда
- **Статус**: proposed
- **Автор**: Architect
- **Дата**: 2025-01-09
- **Описание**: Использовать Vue 3 с Composition API для реализации фронтенда прототипа
- **Обоснование**: 
  - Минимальная настройка через Vite
  - Компонентный подход
  - Реактивность из коробки
  - Легко деплоить на статический хостинг
- **Риски**: 
  - Требует npm/node для сборки
  - Команде может быть незнакомо
- **Альтернативы**: 
  - React + Vite
  - Чистый JS без фреймворка
  - Svelte

### [PROP-002] localStorage как основное хранилище данных
- **Статус**: proposed
- **Автор**: Architect
- **Дата**: 2025-01-09
- **Описание**: Использовать browser localStorage для хранения данных прототипа
- **Обоснование**: 
  - Не требует сервера
  - Работает в браузере
  - Достаточно для демо
- **Риски**: 
  - Данные теряются при очистке кэша
  - Ограничение по размеру (~5MB)
  - Нет синхронизации между устройствами
- **Альтернативы**: 
  - IndexedDB
  - JSON-файл в репозитории
  - SQLite файл

### [PROP-003] GitHub Actions для CI/CD
- **Статус**: proposed
- **Автор**: Architect
- **Дата**: 2025-01-09
- **Описание**: Использовать GitHub Actions для автоматической сборки и деплоя
- **Обоснование**: 
  - Бесплатно для публичных репозиториев
  - Интеграция с GitHub Pages
  - Поддержка scheduled workflows
- **Риски**: 
  - Лимиты бесплатного тарифа
  - Требует настройки
- **Альтернативы**: 
  - Netlify CI
  - Vercel CI
  - Cloudflare Pages CI

### [PROP-004] Эмуляция ролей через dropdown в UI
- **Статус**: proposed
- **Автор**: Architect
- **Дата**: 2025-01-09
- **Описание**: Для прототипа реализовать переключатель ролей в интерфейсе без настоящей авторизации
- **Обоснование**: 
  - Упрощает разработку
  - Достаточно для демонстрации
  - Не требует OAuth/SSO
- **Риски**: 
  - Не является реальной безопасностью
  - Любой пользователь может сменить роль
- **Альтернативы**: 
  - Простая форма логина с фиксированными пользователями
  - JWT токены (избыточно для MVP)

### [PROP-005] Mock API слой для интеграций
- **Статус**: proposed
- **Автор**: Architect
- **Дата**: 2025-01-09
- **Описание**: Создать единый mock-слой для всех внешних интеграций
- **Обоснование**: 
  - Изоляция от внешних сервисов
  - Возможность тестирования без реальных API
  - Явное указание непроверенных мест
- **Риски**: 
  - Может создать ложное чувство завершённости
  - Требует документации
- **Альтернативы**: 
  - Реальные API (невозможно без доступа)
  - Полное исключение интеграций из MVP
