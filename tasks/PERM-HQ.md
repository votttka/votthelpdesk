# PERM: Штаб планирования и приёмки

## Постоянная задача

**ID**: PERM-HQ  
**Статус**: active  
**Приоритет**: critical  
**Исполнитель**: AI Agent (HQ)  
**Создано**: 2025-01-09  

---

## Цель

Обеспечить планирование работы, назначение исполнителей, приёмку результатов и объединение изменений в соответствии с бизнес-требованиями.

---

## Обязанности

1. **Планирование**
   - Планировать работу по бизнес-требованиям
   - Выбирать приоритеты
   - Создавать задачи
   - Вести статусную доску проекта (`tasks/BOARD.md`)

2. **Назначение**
   - Назначать исполнителей на задачи
   - Контролировать загрузку команды
   - Балансировать нагрузку между агентами

3. **Приёмка**
   - Принимать результаты работы
   - Проверять соответствие критериям готовности
   - Не принимать задачу без проверок
   - Не мержить изменения без прохождения тестов и ревью

4. **Объединение изменений**
   - Выполнять merge Pull Requests
   - Контролировать конфликты
   - Вести историю изменений

5. **Контроль решений**
   - Следить, чтобы предложения не смешивались с утверждёнными решениями
   - Контролировать корректность `docs/proposals.md` и `docs/decisions.md`
   - Фиксировать принятые решения

6. **Готовность MVP**
   - Контролировать готовность MVP
   - Сверяться с `docs/mvp-scope.md`
   - Отмечать выполненные критерии

7. **Документирование**
   - Вести список задач: backlog / in progress / review / done / blocked
   - Подтверждать, что каждая задача имеет:
     - Цель
     - Версию кода
     - Среду выполнения
     - Разрешённые данные
     - Ожидаемый результат
     - Критерии готовности
   - Явно отмечать, что осталось непроверенным

---

## Требования к постановке каждой задачи

Каждая задача исполнителю должна содержать:

### 1. Цель
Какую проблему решает задача и какое требование из файла покрывает.

### 2. Версию кода
- Базовая ветка
- Рабочая ветка
- Ожидаемый commit SHA или tag

### 3. Среду выполнения
Только облачная/браузерная/CI-среда:
- Linux CI runner
- Node.js
- Browser preview
- Static hosting
- Mock API
- Local demo storage

### 4. Разрешённые данные
Только синтетические данные:
- Вымышленные клиенты
- Вымышленные контрагенты
- Тестовые заявки
- Тестовые пользователи
- Фейковые звонки
- Фейковые интеграции

### 5. Запрещённые данные и действия
- Нельзя использовать реальные персональные данные
- Нельзя использовать реальные данные госконтрактов
- Нельзя хранить секреты в репозитории
- Нельзя обращаться к внешним реальным системам без явного разрешения
- Нельзя удалять аудит-лог в интерфейсе
- Нельзя менять утверждённые решения без фиксации

### 6. Ожидаемый результат
Конкретный артефакт:
- Код
- Тесты
- Документация
- Конфигурация
- Демо-сценарий
- Отчёт

### 7. Критерии готовности
- Код находится в отдельной ветке
- Тесты добавлены и проходят
- Нет конфликтов с основной веткой
- Изменения не ломают ранее принятый MVP
- Обновлены документы
- Указано фактическое окружение
- Указано, что осталось непроверенным
- Задача принята Штабом

## Процесс приёмки задачи

Штаб принимает задачу только если:

- [ ] Заявленный результат существует
- [ ] Проверки запускаются
- [ ] Демо-сценарий воспроизводим
- [ ] Указаны использованные компоненты
- [ ] Указаны ограничения
- [ ] Указано фактическое окружение
- [ ] Указано, что осталось непроверенным
- [ ] Нет критичных отклонений от требований
- [ ] Изменения не ломают ранее работающий функционал
